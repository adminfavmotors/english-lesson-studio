# Lesson Studio: направление платформы

Цель — собственная образовательная платформа учителя с несколькими учениками, библиотекой материалов, занятиями, домашними заданиями и историей прогресса. A Better Life — первый учебный материал, а не структура всей платформы.

## Согласованные среды

- Публичный сайт учителя: представление и подход, курсы, цены, раздел знаний, запись на пробный урок. Языки: польский, украинский, английский. Пока не реализован.
- Кабинет учителя: ученики и их карточки; отдельная библиотека заданий по уровню, навыку, теме и типу; далее расписание, занятия, домашние работы и проверка.
- Кабинет ученика: назначенные материалы и домашние работы, обратная связь и прогресс; синхронная комната для урока с учителем.

Наполнение библиотеки: описание задания → набросок с помощью ИИ → доработка → Codex добавляет структурированный материал → материал появляется в библиотеке. Встроенный генератор на API пока не требуется.

## Реализованный первый шаг

`teacher_students` хранит независимые записи учеников: UUID, владелец аккаунта, имя, почта, уровень, статус, цели, приватные заметки, даты и версия. Аккаунты учителей используют Supabase Auth; база ограничивает доступ владельцем. Данные текущего занятия в `lesson_private.sessions` остаются отдельно.

В «Учениках» доступны добавление, карточка, редактирование, архив/восстановление, поиск, фильтры и пагинация. Сведения об истории занятий пока явно обозначены как будущий раздел.

## Дальнейшее развитие, по одной доработке

1. Независимая библиотека структурированных заданий с метаданными уровня/навыков/темы.
2. Занятие как связь ученика с выбранными материалами и результатами; существующий документ общей сессии не использовать как общий список учеников.
3. Назначение домашних работ, ответы и проверка с историей у конкретного ученика.
4. Кабинет ученика и отображение настоящего прогресса из сохранённых результатов.
5. Публичный сайт на трёх языках с согласованным содержанием учителя.

Не добавлять фиктивные занятия, оценки, прогресс, цены или биографию для заполнения рабочего интерфейса. Примеры для проверки должны быть явно тестовыми и изолированными от рабочих данных.
