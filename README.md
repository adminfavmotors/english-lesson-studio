# Lesson Studio

Основа образовательной платформы: кабинет учителя со списком учеников, независимая библиотека и учебная комната. В библиотеке — 30 оригинальных уроков A1. Прежний материал Unit 14 «A Better Life», страницы 128–129, доступен через отдельную учебную комнату. React + TypeScript + Vite; обычный CSS. Данные кабинета, библиотека и общие учебные сессии используют отдельный бесплатный проект Supabase `english-lesson-studio` в организации `favmotors`.

Рабочий сайт: https://english-lesson-studio.vercel.app . Раздел учеников: https://english-lesson-studio.vercel.app/teacher/students . Направление развития описано в `PLATFORM.md`.

Интерфейс кабинета и все 30 уроков A1 — на английском: инструкции, определения слов, правила, объяснения ответов, критерии, домашняя практика и рекомендации учителю. Каталог использует реальные английские метаданные уроков; отдельный слой временных переводов удалён. Имена, заметки и другие данные пользователя отображаются в том виде, в котором введены.

## Задания и уроки

Библиотека: https://english-lesson-studio.vercel.app/teacher/materials . Программа из 30 уроков и прямые ссылки находятся в [docs/A1-CURRICULUM.md](docs/A1-CURRICULUM.md), источники и методические ограничения — в [docs/A1-METHODOLOGY.md](docs/A1-METHODOLOGY.md).

- Поиск по названию и теме, фильтры уровня, навыка и темы, коллекция Studio, личные материалы, избранное и страницы по 9 карточек.
- Каждый урок содержит 8 этапов: повторение из памяти, словарь и языковая опора, текст/диалог с вопросами, практика, разговорная задача, письмо, самооценка и домашняя практика. Ориентир — 45 минут с учителем и отдельно 10–15 минут дома.
- В сумме 90 проверяемых блоков и 300 вопросов; выбор ответа, пропуски, соответствия и сборка предложения. После проверки доступны объяснения. Речь и свободное письмо проверяет учитель по критериям.
- Ключи и рекомендации видны в преподавательском предпросмотре; отдельная зелёная версия ученика открывается по ссылке. Черновики разделены по материалу, версии и роли и сохраняются **только в текущем браузере**. Эта практика ещё не связана с общей сессией или карточкой ученика, её результаты не отправляются учителю.
- Для аудирования предоставлен текст: его читает учитель либо английский голос устройства при наличии. Студийных аудиофайлов, записи микрофона и оценки произношения нет.
- Экспорт урока и «Пример JSON» дают образец для подготовки нового материала с ИИ или вручную. После входа «Добавить урок» принимает один JSON-объект, проверяет структуру и создаёт личный материал. Прямой генератор на платном API не подключён.

Коллекция доступна без аккаунта; импорт и избранное требуют того же кабинета учителя, что и список учеников. `lesson_materials` и `material_favourites` защищены RLS: общие уроки доступны для чтения, личные материалы и избранное — владельцу. Импорт не меняет общую коллекцию. Для практики другого аккаунта личный материал пока не назначается и не расшаривается. При недоступности облака используется встроенная копия 30 уроков A1.

Исходники курса находятся в `scripts/a1/`. После правок выполнить `npm run content:build`: команда проверяет содержание, обновляет `src/data/a1-lessons.json` и программу. `npm run content:seed:sql` печатает SQL для осознанного обновления общей коллекции администратором; команда сама ничего не отправляет в базу. Повторная загрузка одинакового содержимого не меняет серверную версию. После изменения данных нужно обновить снимок версий `src/data/a1-versions.json` из базы: встроенная и облачная копии должны использовать одинаковые версии. `npm run test:library` проверяет анонимный отказ доступа; с временным `LESSON_TEST_ACCESS_TOKEN` дополнительно проверяет совпадение всех данных и версий для учителя. Сначала применяются миграции `assignment_library` и `material_validation`. Новые версии контента получают новую серверную версию, чтобы старые ответы не оценивались по изменённому ключу; прежние черновики не удаляются.

Для первой полностью английской редакции предусмотрен перенос совместимого черновика из предыдущей версии при отсутствии нового: сохраняются письмо, домашняя работа, самооценка и ответы с прежними ID. Три выбранных русскоязычных варианта урока 19 заменяются соответствующими английскими фразами. Уже сохранённый новый черновик, включая явный сброс, имеет приоритет. Этот перенос ограничен проверенной редакцией; будущие изменения заданий автоматически ответы не копируют.

## Ученики

1. Открыть **Ученики** и выбрать **Создать кабинет**. Указать собственную почту и пароль (не менее 10 символов).
2. Подтвердить адрес по письму Supabase. После подтверждения можно вернуться на страницу и войти с почтой и паролем.
3. Нажать **Добавить ученика**. Обязательно только имя; почта, уровень A1–C2, статус, цели и заметки заполняются при необходимости.
4. Открыть карточку по имени или стрелке. Редактирование сохраняется кнопкой; архивирование обратимо, физического удаления нет.
5. Поиск по имени, фильтры статуса/уровня и страницы по 20 записей обрабатываются сервером. Кнопка обновления и возвращение в окно загружают актуальные данные.

Вход в аккаунт независим от преподавательских приглашений на урок. Таблица `public.teacher_students` закрыта для анонимных запросов; RLS ограничивает чтение и изменения владельцем аккаунта. Клиент не задаёт `owner_id` и не может изменить владельца. Поле `version` защищает от перезаписи более свежей карточки с другого устройства. Пароли и серверные ключи в исходниках не хранятся. Нужен интернет; очередь автономного редактирования карточек пока не добавлена.

Данные учеников не записываются в общий документ текущего упражнения. Автоматическая связь с занятиями, домашними работами и их прогрессом будет отдельной доработкой. Тестовые ученики с изображений `docs/students-*-qa.png` созданы только в изолированной имитации API, в рабочей базе их нет.

Регистрация использует существующий email-провайдер Supabase с подтверждением адреса. Его ограничения доставки и частоты отправки сохраняются; отдельный SMTP не подключался. Для автоматического возврата после письма в Supabase Auth → URL Configuration должны быть разрешены публичный домен и нужные локальные адреса. Даже без автоматического возврата после подтверждения можно открыть страницу кабинета вручную и войти.

## Запуск в Windows / PowerShell

Нужен Node.js 22.18+ или 24 LTS. В этой среде установлен Node.js 24.12.0, зависимости уже установлены.

```powershell
Set-Location -LiteralPath 'H:\проект для англ'
npm run dev -- --port 5173 --strictPort
```

Открыть http://127.0.0.1:5173/ . Остановить сервер: Ctrl+C в его терминале. Если порт занят уже работающим экземпляром этого проекта, использовать открытую страницу; для другого порта поменять значение `--port`.

На другом компьютере после копирования исходников сначала выполнить `npm ci` с подключением к интернету. Вход, загрузка библиотеки и общая сессия требуют подключения к интернету; локальный сервер должен продолжать работать, пока приложение не опубликовано на хостинге. Не открывать `index.html` двойным щелчком.

```powershell
npm run build
npm run preview -- --port 4173 --strictPort
npm test
```

`build` проверяет TypeScript и создаёт папку `dist`. `preview` открывает собранную версию на http://127.0.0.1:4173/ . В локальном режиме прогресс привязан к origin браузера. В общей сессии ответы сохраняются в Supabase и восстанавливаются по той же ссылке независимо от браузера, компьютера и адреса frontend.

## Separate workspaces

- Entry: http://127.0.0.1:5173/
- Teacher library: http://127.0.0.1:5173/teacher/materials
- Teacher students: http://127.0.0.1:5173/teacher/students
- Teacher classroom: http://127.0.0.1:5173/teacher/classroom
- Student classroom: http://127.0.0.1:5173/student/classroom
- Student material: http://127.0.0.1:5173/student/lessons/a1-01

Teacher and student pages have separate entry components and navigation. There is no role switch inside the student classroom. Canonical paths do not accept a role override through query parameters; previous root links redirect for compatibility. Teacher previews open the student URL in a separate tab.

Local classroom drafts and browser broadcast channels are independent for the two workspaces. Existing local work is retained as independent snapshots. Different tabs of the same workspace still synchronise locally; teacher/student collaboration uses a shared lesson invitation.

The public homepage links to one `/login` form. Trusted roles come from the server; teacher routes and the library require a teacher membership. Students join lessons through invitations after signing in. Google sign-in and individual material assignments remain future work. See [docs/ACCOUNT-ACCESS.md](docs/ACCOUNT-ACCESS.md).

## Общая сессия на разных устройствах

1. Открыть **Задания → A Better Life → Открыть комнату** в режиме **Teacher**.
2. Заполнить **Student and lesson**: имя, уровень, название и номер занятия. В правой панели выбрать дату, время и длительность.
3. Нажать **Invite student → Create shared lesson**. Данные занятия и настройки таймера переносятся; упражнения начинают с пустыми ответами.
4. Скопировать **Student lesson link** и передать ученику.
5. Через **Show my teacher link** сохранить собственную преподавательскую ссылку. Эта ссылка открывает тот же урок на другом компьютере с преподавательскими правами.
6. Для продолжения открывать прежние ссылки, а не создавать каждый раз новую сессию.

Ученическая ссылка позволяет писать ответы, отмечать выполнение и повторять Exercise 1. Таймер всего урока настраивает учитель. Оценки, скрытие текста Reading и сброс остальных упражнений доступны только преподавательской ссылке. Изменение адреса ученической среды на учительский не повышает права приглашения: роль возвращает база по секрету, после чего открывается соответствующая среда.

Полная ссылка является доступом к сессии. Секрет расположен после `#` и передаётся базе в заголовке запроса, а не в query-параметрах сервера frontend. Преподавательскую ссылку следует хранить у себя; ученику предназначена отдельная ссылка.

Видимые изменения отправляются после короткой паузы ввода; второе активное окно проверяет изменения каждую секунду, фоновое — каждые четыре секунды. Это HTTP-синхронизация с коротким опросом, без WebSocket. Обновления обычно появляются в течение 1–2 секунд в активном окне. Пока версия урока не менялась, база возвращает только метаданные, без полного документа.

При потере сети работа помещается в локальную очередь и отправляется после восстановления связи. Очередь сохраняется при обновлении той же вкладки, если хранилище браузера доступно. Ответы разных упражнений не перезаписывают друг друга. Одновременное редактирование одного поля разрешается по порядку поступления на сервер; совместного редактирования текста по символам здесь нет.

## Публикация на Vercel

Для ссылки, доступной с другого компьютера, frontend нужно опубликовать. Адреса `localhost` / `127.0.0.1` открывают локальный компьютер получателя и не являются публичными приглашениями. После публикации новые приглашения автоматически будут содержать публичный домен.

Загрузить исходники и `package-lock.json` на GitHub, импортировать репозиторий в Vercel:

- Framework Preset: **Vite**.
- Build Command: `npm run build`.
- Output Directory: `dist`.
- Install Command: `npm ci`.
- Root Directory: корень, если исходники лежат в корне репозитория.

Настройки подключения уже находятся в `src/backend.config.ts`; секретных серверных ключей и дополнительных переменных окружения для текущего подключения не требуется. Это публичный publishable key, безопасность данных обеспечивается приглашениями и SQL-проверками. Миграции уже применены к подключённому проекту, повторно запускать их при публикации не нужно.

`npm test` запускает локальные тесты без интернета. `npm run test:cloud` отдельно проверяет настоящую базу: создаёт тестовую сессию, проверяет запись, роли, изоляцию и сброс; в конце очищает ответы этой тестовой сессии.

## Что реализовано

- 1: пять вопросов a/b, нейтральный выбор до проверки, результат из пяти, подсветка верного и неверного вариантов, повтор и ключ ответов преподавателя.
- 2: индивидуальная практика Review → Recall → Self-check. Пять исходных пар, устный или письменный ответ по одной карточке, раскрытие оригинала, самооценка и повтор только трудных карточек. Двухминутный таймер на этапе Review необязателен.
- 3–4: письменные ответы, пример диалога, заметки для устной работы и отметка выполнения.
- 5–9: обсуждение, текст Maja, девять вопросов и отдельные ответы Student A / B, заметки и пошаговое интервью по вопросам Exercise 6 с переключением спрашивающего.
- 10–11: исходный блок грамматики, вопросы к текстам и пять свободных дополнений. Преподаватель оценивает ответы вручную.
- 12: шесть тематических карточек с заметками.
- 13–14: место для оригинальных аудиозаписей, стандартный аудиоплеер при наличии файла, восемь полей диктанта и восемь слов-подсказок. Автоматической проверки аудирования и устной речи нет.
- Просмотр оригинального изображения в диалоге и открытие его в полном размере.

## Структура

```text
src/lesson.ts       Метаданные, исходные инструкции, тексты, вопросы, ключи и типы всех упражнений
src/Exercises.tsx   Переиспользуемые механики упражнений, интервью, таймер, аудио и проверка
src/App.tsx         Оболочка, разделы, режимы и панель преподавателя
src/store.ts        Переключение между локальным хранилищем и общей сессией
src/store-model.ts  Типы и слияние локальных документов
src/session-api.ts  RPC API базы, разбор приглашений и навигация
src/session-sync.ts Очередь изменений, повтор, загрузка и синхронизация
src/SessionPanel.tsx Создание сессии, ссылки и состояние подключения
src/LessonWorkspace.tsx Карточка ученика, календарь и общий таймер
src/lesson-workspace.ts Чистая логика таймера и календарной сетки
src/backend.config.ts Публичный адрес Supabase и publishable key
supabase/migrations/ Воспроизводимая схема базы и её ограничения
src/styles.css     Визуальная система, адаптивная вёрстка и состояния элементов
src/main.tsx       Запуск React и локальные файлы шрифтов
public/unit14.jpg  Предоставленное изображение учебника
public/audio/      Оригинальные записи, добавляемые позднее
tests/store.test.ts Проверки слияния, сброса, повреждённых данных и состава урока
VERIFICATION.md    Выполненные проверки и границы проверки
```

Описание упражнения (`Exercise`) хранится отдельно от состояния пользователя. Все упражнения имеют общий ID, номер, раздел, инструкцию и дискриминирующий `type`; конкретный тип задаёт содержимое и правила проверки. Ответы, оценки и завершённость адресуются ключами `<exerciseId>.answer.<questionId>`, `<exerciseId>.answer.<questionId>.grade` и `<exerciseId>.complete`. Для парной работы ключ дополнен ролью.

Слияние выполняется по полям с логическим временем и идентификатором вкладки. Правки разных полей объединяются; при одновременном редактировании одного поля выигрывает более поздняя запись, при равном времени — стабильный порядок идентификаторов. Сброс сохраняет пустые записи, чтобы старое состояние другой вкладки не восстанавливало ответы.

В общей сессии порядок правок назначает сервер, а не часы компьютеров. Одновременные правки разных полей сохраняются независимо; для одного поля выигрывает последняя полученная сервером правка. Версия сброса хранится отдельно для каждого упражнения: старая очередь не восстанавливает сброшенные ответы.

Для следующего учебника можно добавить структурированные данные с теми же типами и подключить их к оболочке. Это ручная оцифровка урока; универсального конвертера изображений здесь нет.


## Обновлённое рабочее пространство занятия

- **Шрифт:** локальный Source Sans 3 с поддержкой кириллицы. Инструкции и ответы 16–18 px, текст Reading 18 px, обычный шрифт без декоративных засечек.
- **Teacher:** синяя цветовая тема, редактируемая карточка Student & lesson и панель Session controls справа.
- **Student:** зелёная тема, приветствие, данные текущего занятия и общий таймер без управления им.
- **Данные:** имя и уровень ученика, название и номер занятия. Это данные одной сессии, а не отдельная CRM или каталог учеников.
- **Календарь:** выбор даты текущего занятия, переходы между месяцами, ввод даты и времени. Это внутреннее расписание текущей сессии, без интеграций с внешними календарями. Часовой пояс подписан: Europe/Warsaw.
- **Общий таймер:** преподаватель задаёт длительность от 1 до 240 минут (по умолчанию 60), запускает, ставит на паузу, продолжает и сбрасывает. Таймер отображается также в закреплённой верхней панели. Ученик видит тот же отсчёт и состояние; управление закрыто как в интерфейсе, так и в SQL API.
- **Exercise 2:** собственный таймер упражнения на две минуты сохранён отдельно от общего таймера урока.
- **Сброс ответов:** очищает упражнения и их прогресс, сохраняя данные ученика, дату, время и общий таймер.
- **Узкое окно:** навигация открывается кнопкой меню, а календарь и таймер — через Open session controls. Панели закрываются Escape; Tab остаётся внутри открытой панели.

Данные и таймер хранятся в полях `lesson.*` того же документа Supabase. В приложении используется поправка на время сервера, чтобы разные часы компьютеров не давали разный отсчёт. При редактировании нескольких учительских вкладок настройки разрешаются по порядку получения базой, как и другие поля.


## Exercise 2 — практика для одного ученика

Задание адаптировано из исходной парной работы. Исходная инструкция сохранена в свёрнутом блоке Original textbook instruction. Все пять фраз и соответствующих утверждений взяты из Exercise 1.

1. **Review:** ученик изучает пять пар предложений в своём темпе. При желании включает двухминутный таймер. Его истечение переводит к карточкам, но ждать его окончания не требуется.
2. **Recall:** показывается одна фраза, соответствующее утверждение скрыто. Ученик вспоминает его вслух или записывает ответ; поле необязательное.
3. **Reveal answer:** открывает исходное утверждение. Дословное совпадение не требуется — ученик сопоставляет смысл.
4. **I remembered / Practise again:** самооценка переводит к следующей карточке.
5. **Self-check:** итог по пяти карточкам и возможность повторить только отмеченные трудными или все карточки. Start over возвращает к этапу Review.

Письменный ответ, текущая карточка, раскрытие и самооценки сохраняются. В общей сессии преподаватель видит тот же этап работы через Supabase. Состояние практики хранится в `<exerciseId>.memory.*`, письменные ответы — в `<exerciseId>.answer.recall.*`. Ученик может перезапустить только Exercise 1 и Exercise 2; остальные права преподавателя сохранены. Общий таймер урока работает независимо.
